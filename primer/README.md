# 基礎サブプロジェクト（primer）

フェーズ 0–12 で tokenizer から GPU 推論まで動かし、13–17 で LoRA SFT に入る。その並行でもう一本、**数の表と三重ループから次トークンまで** を手で書く学習路を切る。このファイルは構成・形式・範囲の正本である。教材本体（HTML）とスクリプトは、この計画を承認してから作る。

## 結論

既存ノート（[`notes/learn-llm-basics.html`](../notes/learn-llm-basics.html) など）は、Qwen3.5 の **形と実測** を説明する。足りないのは、そこに出てくる式を **電卓と `for` で再現できる** ことである。

このサブプロジェクトは GPU も Hugging Face も使わない。Python の二重リストと三重ループで行列積を書き、2 層ネットの勾配を数値で確かめ、文字単位の超小型言語モデルを学習させる。到達点は「`softmax(QKᵀ / √d) V` の文字を、3 トークン × 4 次元の表として全部印刷できる」こと。9B を再実装することではない。

**教材の形式は HTML（KaTeX + 数値表 + SVG）+ 隣に置く原始的な `.py`。索引と計画はこの Markdown。** Jupyter は使わない。理由は下の「形式の比較」に書いた。

## なぜ今か

[`notes/learn-llm-basics.html`](../notes/learn-llm-basics.html) はこう書く。

> attention は `softmax(Q·Kᵀ / √d) · V`

読者が高校数学までで、大学で数学を専攻していないとき、ここで詰まる点は Transformer の思想ではなく次である。

- `·` は内積なのか行列積なのか
- `ᵀ` は表をどうひっくり返すのか
- ベクトルの長さ `d` で割るのは「気持ち」なのか計算の必然なのか
- コンピュータはそれを何重のループでやっているのか
- 学習（フェーズ 15）で動く backward は、そのループのどこを逆に辿るのか

既存ノートが厚いのは **動かした結果**（VRAM、tok/s、Base と Instruct）である。式の中身は「1 行で書いて先へ進む」判断になっている。ライブラリ（`torch.nn.Linear`、`numpy.matmul`、`transformers`）は正しい答えを出すが、三重ループを隠す。隠された三重ループが、GPU が速く、Q4 が効き、LoRA が小さな行列の積で済む理由そのものなので、基礎の学習には不向きである。

混同しやすい対比:

| 既存の弧 | このサブプロジェクト |
| --- | --- |
| Qwen の BPE で「山田」が何トークンか | 文字を 1 トークンとみなす（BPE は [`notes/pipeline.md`](../notes/pipeline.md) に既にある） |
| 9B の forward を llama.cpp に任せる | 3 トークンの forward を自分のループで出す |
| LoRA を `target_modules` で当てる | `ΔW = BA` を 2×3 と 3×4 の積として見る |
| 量子化で要素を 4 bit にする | 先に fp32 の要素がメモリ上で何バイトかを見る |

どちらも必要で、置き換えではない。13–17 は止めない。primer は GPU 不要なので、推論待ちやクラウド Agent 上でも進められる。

## 読者と前提

- 高校数学まで。ベクトルは「数を並べたもの」、一次関数、指数・対数、場合の数と確率はある、として書く
- 大学の線形代数・解析は仮定しない。固有値、Jacobian、測度、情報理論の式は出さない
- クラウド / HTTP / CLI / WSL の入門はしない（リポジトリの前提どおり）
- Python の `for` / リスト / 関数は読める。NumPy・PyTorch は **知らない方がよい**（先に知っていると、自分で書いたループを読まなくなる）
- 用語は初出で 1 文定義する。`logits` / `softmax` / `embedding` / `attention` は英語のまま

高校からの橋（本文で毎回この粒度で書く）:

| 高校で見たもの | ここで使う形 |
| --- | --- |
| 数直線上の点 | **スカラー**（一つの数） |
| 速度のように成分が並んだ量 | **ベクトル**（1 列または 1 行の表） |
| 表、一次変換 | **行列**（長方形の表。ベクトルを別のベクトルへ写す機械でもある） |
| 成分の積の和 | **内積**（同じ長さの 2 ベクトル → スカラー） |
| 接線の傾き | **微分**。「少し動かしたときの変化」を先に数値で測り、公式は後から |
| 合成関数 | **連鎖律**。`z` が `y` 経由で `x` に依存するとき、傾きは掛け算 |
| 対数 `log` | 損失 `−log p`。正解の確率 `p` が 1 なら 0、小さいほど罰が大きい |
| 確率の合計 1 | **softmax**。好きな点数（logits）を、正で合計 1 の内訳にする |

出さないもの: ε-δ、重積分、固有分解、テンソルの抽象定義。「テンソル」は「3 次元以上の数の塊（表の表）」とだけ言い、すぐ具体的な shape に落とす。

## 形式の比較と決定

数式の見え方と、手元で動かす学習のしやすさだけを見る。論文を書く形式ではない。

| 形式 | 数式 | 図 | 実行 | 既存ノートとの一貫 | git 差分 | 見方 |
| --- | --- | --- | --- | --- | --- | --- |
| Markdown（`$...$`） | GitHub / Cursor では足りることが多い。行列の揃った表示は弱い | mermaid / 表 | 別ファイル | [`notes/pipeline.md`](../notes/pipeline.md) と同じ | 強い | エディタのまま |
| Jupyter (`.ipynb`) | 強い | matplotlib | セルが本体 | リポジトリに無い | JSON で弱い | 別アプリ |
| HTML + KaTeX + SVG | 強い | 既存 `learn-*.html` と同じ手 | 別の `.py` | **既存教材と同じ見た目** | HTML は長いが追える | ブラウザ |
| 解説とコードを 1 つの `.py` に混在 | コメント内の疑似式だけ | ASCII | そのファイル | 既存スクリプトに近い | 強い | ターミナル |

**採用: 1 レッスン = 1 つの HTML + 0 または 1 つの `.py`。地図と進行はこの README。**

なぜ HTML か。

- 既存の学習ノート A/B・GPU・量子化がすでに HTML で、callout（定義 / 警告 / このマシン）と SVG の言語が読者の手元にある
- attention の「誰が誰を見るか」は表だけでは足りず、既存ノートと同じ SVG が要る
- KaTeX で一般式を一度出し、**すぐ下に同じ計算を数値の表で繰り返す**。高校数学の読者には `pmatrix` より 2 行 3 列の表の方が先に入る
- ブラウザで開くコストは、すでに `notes/learn-*.html` で払っている

なぜ Jupyter を却下するか。

- セルの実行順と「隠れ状態」が、ライブラリと同じ種類の隠蔽になる
- 差分が読みにくく、このリポジトリの「なぜそのコマンドか」を残す流儀と合わない
- 依存（jupyter / ipykernel）が増える。primer の制約は「標準ライブラリで動く」こと

なぜ解説を `.py` の docstring だけにしないか。数式と SVG が落ちる。スクリプトは **検証可能な計算** に専念し、物語は HTML が持つ。

各 HTML の型（既存 `learn-*.html` に合わせる）:

1. 短い結論
2. 用語の定義（1 文）
3. 一般式（KaTeX、1 回）
4. **同じ式の数値表**（2×3 など。手計算できる大きさ）
5. 混同ポイント
6. スクリプトの実行コマンドと、期待する出力の抜粋
7. 確認問題（`<details>`）

数式の書き方ルール:

- 一般式は KaTeX。具体例は HTML の `<table>`（要素は小数 2〜3 桁）
- 教科書の列ベクトル `y = Wx` と、実装の行ベクトル `y = xW` が逆に見える。**このサブプロジェクトは行ベクトル（トークン 1 個 = 表の 1 行）に固定する**。PyTorch の `x @ W` と同じ。列ベクトルは「混同ポイント」で一度だけ触れ、本文では使わない
- `Σ` は「全部足す」。アインシュタイン縮約は出さない
- 勾配は矢印記号 `∇` より「この成分を動かしたときの損失の変化」と書く

## カリキュラム

全部で 11 本（00–10）。4 部に分ける。1 本は「HTML を読む + スクリプトを 1 回走らせて表が一致することを見る」まで。合格は下の「進め方」。

### 第 1 部 — コンピュータ上の行列

GPU の中も、結局はこの部の三重ループである。

**00 地図**（`00-map.html`）  
このサブプロジェクトが既存ノートのどの式を分解するか。GPU 不要であること。行ベクトル流儀。次に 01 を開く。

**01 ベクトルと行列**（`01-vectors.html` / `01_vectors.py`）  
数の並びを表として見る。和とスカラー倍をループで書く。shape を `(行, 列)` と固定する。  
混同: 「ベクトル = 矢印」ではなく「矢印の成分の表」。幾何は一次変換の絵を 1 枚だけ（2D の拡大）。

**02 メモリと浮動小数点**（`02-float.html` / `02_float.py`）  
二重リストは行優先（先に行、その中に列）。`0.1 + 0.2` が 0.3 にならないことを印刷する。**浮動小数点**は「数を有限ビットで近似する書き方」。fp32 は 4 バイト、fp16 / bf16 は 2 バイト。ここが量子化ノート（要素を 4 bit まで削る）の土台。  
混同: 「コンピュータは実数を正確に持つ」。持たない。Q4 はさらに粗くした版。

**03 内積と行列積**（`03-matmul.html` / `03_matmul.py`）  
内積 = 成分の積の和。行列積 = 「左の各行と右の各列の内積」= 三重ループ。手計算できる 2×3 と 3×2 をスクリプトの `assert` と一致させる。転置は行と列の入れ替え。計算量はおおよそ `行 × 共有辺 × 列` 回の積。  
ここで初めて「なぜ GPU が行列積専用の回路を持つか」を 1 段落で書く。数学が違うのではなく、**同じ掛け算を膨大に**やるから。  
混同: `A * B`（要素ごと）と `A @ B`（行列積）。primer の自前関数は行列積だけにする。

### 第 2 部 — ニューラルネットの最小形

**04 線形層と活性化**（`04-linear.html` / `04_linear.py`）  
`y = x @ W + b`。`W` の shape は `(入次元, 出次元)`。線形を 2 回重ねると 1 回の線形に潰れる（高校の「一次関数の合成は一次」）。だから途中に折れ線が要る。**ReLU** は「負なら 0、正ならそのまま」。  
スクリプト: 2 層を線形だけのときと ReLU 入りで、同じ入力の出力が違うことを示す。XOR が一本の直線で分けられない話は表で十分（散布図ライブラリは使わない）。

**05 softmax と損失**（`05-softmax.html` / `05_softmax.py`）  
**logits**: まだ確率ではない生スコア（[`notes/pipeline.md`](../notes/pipeline.md) と同じ定義）。softmax で正・合計 1 にする。temperature は logits を割る操作で、既存パイプラインの言葉と接続する。  
損失は正解クラスの `−log p`（**cross-entropy** の 1 件分）。`p=1` なら 0、`p=0.01` なら約 4.6。事前学習が最適化している唯一の数字、という学習ノート A の 5 節へここで数学的に着地する。  
混同: softmax は「一番大きいものを 1 にする」関数ではない。最大は大きくなるが、他も残る。

**06 勾配と 2 層ネット**（`06-backprop.html` / `06_backprop.py`）  
勾配は「その重みを少し動かしたとき、損失がどちらへどれだけ動くか」。先に **数値微分**（足して引いて差を見る。高校の平均変化率そのもの）。次に、合成の傾きは掛け算であるという連鎖律を 2 段で。最後に手書き backward で数値微分と `assert` で一致させる。パラメータを少し逆向きに動かすと損失が落ちる（勾配降下）。題材は 2 入力の AND か XOR（小さく、出力を目で追える）。  
混同: 「学習 = 魔法で重みが決まる」ではなく「損失の坂を下る」。フェーズ 15 の optimizer は、この更新の手数を増やす道具である。

### 第 3 部 — 言語モデルの最小形

BPE は使わない。文字を 1 ID にする。語彙は数十。既存フェーズ 1 の tokenizer デモと役割が被らないように、わざと原始的にする。

**07 数え上げの bigram**（`07-bigram.html` / `07_bigram.py`）  
**言語モデル**を「これまでのトークン列の次に来る ID の確率分布」と定義する。最も原始的な実現は、隣り合う文字対の回数表（bigram 行列）である。正規化すると、各行が softmax の出力と同じ形（合計 1）になる。短い日本語（例: 架空の姓名を数個）で表を印刷し、サンプリングで続きを出す。  
混同: これが「意味を理解している」のではない。隣の頻度である。それでも「次を当てる」という目的関数は 9B と同じ。

**08 embedding とニューラル bigram**（`08-embed.html` / `08_embed.py`）  
回数表の代わりに、ID で表の 1 行を引く（**embedding**）。そのベクトルに線形層を掛けて語彙サイズの logits を出す。one-hot と行列積が同じ結果になることを小さな表で示す。だから実装は「行を引く」だけでよい。  
スクリプト: 07 と同じコーパスで、ランダムな `W` の損失を出し、06 の更新を 1 回以上かけて損失が動くこと。

**09 attention**（`09-attention.html` / `09_attention.py`）  
学習ノート A の式を、トークン 3・次元 4 で全部印刷する。Q / K / V はそれぞれ `x @ Wq` など。内積、`√d` で割る理由（内積の分散が大きくなると softmax が尖る）、因果マスク（未来の位置を非常に小さい数にして見えないようにする）、V の加重平均。KV cache は「過去の K, V の行を捨てずに残す」と、同じ表で 4 トークン目だけ足す。  
GQA や Gated DeltaNet はここでは実装しない。既存ノートへ「巨大版・変形版がある」とリンクする。  
混同: attention は「重要語を見つける AI」ではなく、**今の行の Q と、残した K の内積で重みを作り、V を混ぜる**計算である。

**10 超小型 LM と本リポジトリへの橋**（`10-tiny-lm.html` / `10_tiny_lm.py`、橋の節は HTML 内）  
文字 embedding → 1 層 attention → 線形 → softmax を、数十〜百文字で学習し、生成する。過学習して学習文を真似るところまででよい（フェーズ 15 の「過学習を自分の目で見る」の玩具版）。  
橋:

- 9B の各行列はこれの行と列が数千〜数十万になったもの。要素数の合計がパラメータ数
- decode が重いのは、この `W` を毎トークン VRAM から読むから（学習ノート A の 7 節）
- Q4 は 03 で見た浮動小数点の要素を粗くしたもの
- LoRA は巨大な `ΔW` を、小さな `B` と `A` の積で持つ（レッスン 03 の行列積そのもの）
- ここで初めて `numpy.matmul` を 1 ブロック出し、自分の三重ループと同じ数字になることを `assert` する。「ライブラリが隠蔽していたもの」を、隠す前に自分で書いたあとで見る

## スクリプトの制約

- Python 3.12。`.venv/bin/python primer/scripts/….py` で単体実行。引数なしでデモ入力を持つ
- 標準ライブラリのみ（10 の対照ブロックだけ numpy を許可。未インストールならそのブロックを skip し、自前ループの結果は必ず出す）
- GPU 禁止。`torch` 禁止。`transformers` 禁止
- 入力はスクリプト内の定数。ネットから何も取らない
- 出力は「表」が主。`print` で行・列が目で追えること。期待値は HTML に抜粋し、コード側は `assert` で固定
- 乱数が要るところは `random.seed(0)` で固定
- 共通化は 08 以降でよい。01–03 は三重ループを毎回書く（飽きれ、が目的）

ライブラリを後で使うときの順序（守る）:

1. 自前ループ
2. 同じ数字を numpy で 1 行
3. （このサブプロジェクトの外）同じ概念が `nn.Linear` / llama.cpp のカーネルになっている

2 を飛ばして 3 に行くと、また隠蔽に戻る。
