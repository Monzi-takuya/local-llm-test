# フェーズ 5: 計測と比較

同じプロンプトで、サイズ・量子化・コンテキストの差を手で記録する。表計算やダッシュボードは作らない。

- 依存: フェーズ 3 が理想。最低でもフェーズ 2 の Ollama で代用可
- GPU: 必須。計測中は他の CUDA アプリを止める
- 所要の目安: 数本の固定プロンプトを繰り返す時間

## 学習で押さえること

- 4B と 7B: 速度と日本語の質のトレードオフ
- Q4 と Q5: 品質と VRAM。Q8 は 8 GB では省略してよい
- コンテキスト 2K と 8K: KV キャッシュで VRAM と速度が変わる
- TTFT（最初のトークンまで）と、その後の tok/s は別指標
- Windows ネイティブとの比較は **必須にしない**。WSL で安定すれば十分

## 固定条件

計測のたびに次を揃える。変えたらメモする。

- プロンプト 2 本（日本語の短い指示、英語の短い指示）。[`../results/05-prompts.md`](../results/05-prompts.md) に本文を固定する
- `-n` / max tokens を固定（例: 128）
- 可能なら温度 0 または十分低くし、ばらつきを抑える
- ウォームアップ 1 回を捨て、その後を記録してもよい（やったかどうかを書く）

ランタイムは llama.cpp を優先（timings が読める）。Ollama のみの場合は体感と `nvidia-smi` を正直に書く。

## 手順

### 5-1. 記録テンプレ

[`../results/05-bench.md`](../results/05-bench.md) に、1 行 1 実験で少なくとも次を書く。Markdown の表は使ってよい。

- 日時
- ランタイムと版
- モデル / 量子化
- ngl（または Ollama なら GPU 使用の有無）
- コンテキスト長
- VRAM（生成中の `nvidia-smi`）
- WSL RAM（`free -h` の used）
- TTFT（取れた場合）
- prompt eval tok/s、generation tok/s
- 日本語の明らかな崩れ（あり / なし / 微妙）
- 備考（OOM、dropcache 疑い、`--no-mmap`）

### 5-2. 必須の比較

時間が許す範囲で上から。全部やれなければ、やった番号と省略理由を書く。

1. 4B Q4 vs 7B Q4（GPU 全載せ、コンテキスト 2048）
2. 7B Q4 vs 7B Q5（載る場合のみ）
3. 7B Q4 の `-ngl 99` vs `-ngl 0`
4. 7B Q4 の `-c 2048` vs `-c 8192`（VRAM が許す場合）

### 5-3. コマンドの控え

繰り返すコマンドを [`../scripts/bench.sh`](../scripts/bench.sh) に残す。引数やパスは環境依存なので、実行前に中を読む前提でよい。

## 合格条件

- [ ] 固定プロンプトがファイルに残っている
- [ ] 少なくとも「4B vs 7B」または「GPU vs CPU」の 1 軸は数値が揃っている
- [ ] 各行に VRAM がある
- [ ] 省略した比較には理由がある
- [ ] [`../PROGRESS.md`](../PROGRESS.md) を更新した

## 失敗したとき

| 現象 | まず疑うこと |
| --- | --- |
| 数値が毎回大きく違う | バックグラウンドの GPU 負荷、温度、未ウォームアップ |
| 8K で落ちる | KV キャッシュ。必須ではないので省略して記録 |
| 途中から急減速 | フェーズ 3 と同じ mmap / dropcache |
