# フェーズ 10: monzi-sandbox で 27B 全載せの可否

フェーズ 7 で分かったこと: ローカル RTX 5060 8GB では Qwen3.8-27B Q4 は部分 GPU（`-ngl 30`）で **3.7 tok/s**。対話の目安 8 tok/s 未達。クラウドの意味があるのは **27B を L4 24GB に全載せ**すること。9B 日常はローカルの方が速い。

このフェーズは紙上の機種選定ではなく、`gcloud` が **プロジェクト `monzi-sandbox`** で動く前提で、東京の L4 / `g2-standard-8` が **今このアカウントで作れるか** を確定する。

- 依存: フェーズ 7 の VRAM 見積もり。gcloud ログイン済み（`gcloud config get-value project` が `monzi-sandbox`）
- GPU（ローカル）: 不要
- 課金: **GPU VM は作らない**。クォータと billing の読み取りだけが合格線

## なぜ今これか

紙上では推奨機は `g2-standard-8`（L4 24GB、RAM 32GB）。27B Q4 の GGUF は 16G。全載せ VRAM は重み + KV + バッファで **約 18–22 GB**。T4 16GB は不可。A100 40GB は体感を 9B 級にするが単価が約 4 倍。

この作業で確定すること: ゾーンに L4 があるか、地域クォータ `NVIDIA_L4_GPUS`、グローバル `GPUS_ALL_REGIONS`、請求先が無料枠かどうか。**作れない理由がクォータ不足なのか、無料枠禁止なのかを切り分ける。**

やらなかったこと: GPU VM の create、CUDA 導入、クラウド上の `bench.sh`、A100 の申請、`google-cloud-skill-challenge` への混入。

## 対象（27B 前提）

| 項目 | 値 |
| --- | --- |
| モデル | `Qwen3.8-27B-UD-Q4_K_M.gguf`（16G） |
| 機種 | `g2-standard-8`（8 vCPU / RAM 32GB / L4 1 枚） |
| リージョン | `asia-northeast1` |
| ゾーン候補 | a / b / c（いずれも L4 あり） |
| 使わない | `g2-standard-4`（RAM 16GB = GGUF と同サイズ）、T4、A100（このフェーズ） |

## 手順（読み取り）

サンドボックス外。プロジェクトは毎回 `--project=monzi-sandbox` を付ける（Cloud Run 本番と同居しているため）。

```bash
gcloud config get-value project
# 合格: monzi-sandbox

gcloud billing projects describe monzi-sandbox \
  --format='yaml(billingEnabled)'
# 合格: billingEnabled: true（これだけでは有料アカウントとは限らない）

gcloud compute accelerator-types list --project=monzi-sandbox \
  --filter='zone:asia-northeast1* AND name:nvidia-l4' \
  --format='table(name,zone)'
# 合格: asia-northeast1-a/b/c に nvidia-l4

gcloud compute machine-types describe g2-standard-8 \
  --project=monzi-sandbox --zone=asia-northeast1-a \
  --format='yaml(name,guestCpus,memoryMb)'
# 合格: guestCpus 8、memoryMb 32768

gcloud compute regions describe asia-northeast1 --project=monzi-sandbox \
  --format='yaml(quotas)' | rg -i 'NVIDIA_L4|NVIDIA_A100|NVIDIA_T4|PREEMPTIBLE_CPUS|A2_CPUS'
# 見る場所: NVIDIA_L4_GPUS の limit。0 なら地域クォータ申請が要る

gcloud compute project-info describe --project=monzi-sandbox \
  --format='yaml(quotas)' | rg -i 'GPUS_ALL_REGIONS'
# 見る場所: limit が 0 なら、地域 L4=1 でも GPU VM は作れない
```

GPU insert の可否は Compute API のエラー本文で確定する。**CPU VM の insert は試さない**（`dryRun` でも実体が立つことがある。2026-09-13 に e2-micro が STAGING になり、即削除した）。

見る場所（GPU の 400、insert する場合）:

- `free tier where non-TPU accelerators are not available` → 請求先がまだ無料枠
- `Quota 'GPUS_ALL_REGIONS' exceeded` → グローバルクォータ 0（2026-09-14 再実測でも limit 0）
- それ以外の `ZONE_RESOURCE_POOL_EXHAUSTED` → クォータはあるが在庫切れ

有料化後の再確認は insert しない。`project-info` の `GPUS_ALL_REGIONS` が 0 ならここで止める。

## 合格条件

- [x] `gcloud` の project が `monzi-sandbox`、Compute API 有効、請求先は open
- [x] 東京 a/b/c に `nvidia-l4` と `g2-standard-8` がある
- [x] `NVIDIA_L4_GPUS` と `GPUS_ALL_REGIONS` の limit を記録した
- [x] GPU insert が弾かれた理由（無料枠 / クォータ）を本文で切った
- [x] GPU VM を残していない。既存 Cloud Run を触っていない

## 失敗したとき

| 現象 | まず疑うこと |
| --- | --- |
| `compute.googleapis.com` が無い | `gcloud services enable compute.googleapis.com`（このプロジェクトでは有効済み） |
| 地域 L4=1 なのに create が 400 | `GPUS_ALL_REGIONS=0` か無料枠。両方を見る |
| A100 を取りたい | `A2_CPUS` と `NVIDIA_A100_GPUS` が 0。このフェーズの対象外 |
| Spot が安い | `PREEMPTIBLE_CPUS=0`。Spot は今は使えない |
